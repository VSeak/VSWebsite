# Top Out (Adult Team)

Coaching for the gym's Adult Team, a group instead of one student at a time. Staff sign in; team members don't (yet). Each location (Minneapolis, St. Paul, more added by admins) has a roster, a Team Summary with a Team Focus, and a calendar. Each member has an Intake, Goals, Coach Notes and Check-ins.

## How it's built

- Same shape as Sit Start: `index.html` (header and shell), `styles.css`, plain JS in `js/` loaded as classic `<script>` tags that share one global scope, in the order listed in `index.html`; `boot()` runs last. Don't declare the same top-level name in two files. No build step. supabase-js pinned from jsDelivr.
  - `core.js`: `CONFIG`, page state (`me`), helpers (`esc`, `para`, `flash`, `ask`, `busy`, `crumbs`, field errors), pronouns, dates, grades (`V_GRADES`, `ROUTE_GRADES`, `circuitRange`, `swatch`), `sendLink`.
  - `app.js`: `boot`, `loadMe`, `route`, the leave check and Unsaved marks, sign-in pages, Home (`homePage`), `eventRow` / `KINDS`.
  - `location.js`: a location's tabs, in order Summary (`#/loc/<id>`, where a location opens; the user asked), Calendar, Team; `#/loc/<id>/team` (Team tab: members with chips, Active / Former, + Add Member; the member page's breadcrumb goes back here) and `#/members` (Team Members: everyone you can see with their team chips, a Location: filter incl. On Several Teams; a Home tile for all staff). Both use `loadMembers` / `membersView`. Opening Home resets Active / Former to Active. Members with the same name (in the list shown) get a line under the name: Joined Mon YYYY · email. Add Member first checks for the same first and last name (`notADuplicate`: This Person May Exist on Another Team, each as Name (pronouns), where they are, then Add to <location>; OK is Add New Person; both plain until hovered, `.hover-fill`, the user asked) and lists them: members you can see as links (put the same person on this team via Details instead), the rest from `team_same_name()` (security definer: their id, locations and whether they left). Each has Add to <location>: `team_join_location()` puts them on this team even if the coach doesn't coach their other teams (the user asked: no admin needed), then opens them. Or Add Anyway.
  - `calendar.js`: `#/loc/<id>/calendar` (month grid, the picked day, Coming Up, the event dialogs).
  - `member.js`: `#/member/<id>` (Intake, Goals, Coach Notes, Details).
  - `checkins.js`: the Check-Ins card and its dialog; `AREA_GROUPS`, `byGroup`, `areaChips`, `answered` (shared with summary.js).
  - `summary.js`: `#/loc/<id>` (the Summary tab, first; `/summary` still works). It replaces the coach's spreadsheet: each active member's latest check-in (Check-Ins Since: a date, by default the 1st of the month 6 months back (the user asked), or Show Latest Check-Ins for the latest whenever it was), By Area (Member and Coach averages with how many rated, a count per tag question, Most Wanted and Lowest Rated lines, a highlight when they differ by 1+), What They Said (By Question / By Member), and Team Focus. Next Practice (right column, above What They Said; the user asked): the next event of kind Practice here from today, with what the calendar pop-up shows less the type and location chips (the user said the page makes those obvious) and the Added by line, the linked plan's Focus Areas, its Practice Plan and Open in Calendar (sets `calOpen`, so the pop-up opens). Only active members count (Former ones are left out). Copy Summary (plain text) and Copy Table (tab-separated, one row per member, pastes into a spreadsheet) are for coaches not on the app yet (the user asked). Team Focus shows only here (the strip on the other tabs was dropped once Summary became the first tab; the user asked).
  - `practices.js`: `#/practices` (a Home tile for all staff: search and an Area: filter) and `#/practice/<id>` (the plan: each block with its length, no start or clock times (the user said); About; where it is On the Calendar), Delete is on each list card (the name is a link stretched over the card, so a button fits inside), on the practice page and in the editor (`deletePractice`). Duplicate (by Edit) saves a copy named "<name> (Copy)" at once and opens it in the editor. Practice Plan on the Summary's Next Practice and on a calendar event opens `practiceDialog` instead of the page (the user asked, to stay on the location): the plan, then Edit swaps in the editor's fields (`practiceFieldsHTML`, `wirePracticeForm`, `readPractice`, shared with the editor page); Save redraws the page and reopens the plan; Open Practice Page goes to the page. `#/practice/<id>/edit` and `#/practice/new` (the editor: blocks reorder by grip, the hidden `order` field makes a reorder, add or remove count as unsaved; empty blocks are dropped on save).
  - `admin.js`: `#/staff` and `#/settings` (admins only). Settings has two columns: Locations and Circuit Colors on the left; Check-In Questions and Focus Areas on the right. Every list there reorders by dragging its grip, which replaced the ↑/↓ buttons (the user asked). `wireGrips` / `GRIP` (core.js) are shared with the practice editor: pointer events so fingers work too, listened for on the window (moving the row drops pointer capture), arrow keys when the grip has focus.
- **Same Supabase project as Sit Start** (same URL and key in `CONFIG`). Tables are all `team_*`; `supabase/schema.sql` creates them. Security is in the database: every table checks `team_staff` through `team_is_staff()`, `team_is_admin()`, `team_can_location()` and `team_can_member()`, so a login that is only a Sit Start account signs in and sees nothing (the page shows "No Access").
- **Shared logins:** `auth.users` is shared. Sit Start's sign-up gate, Delete Student, Delete Staff and Deactivate call `login_in_other_app(email)`, which Top Out's schema defines (is the email on `team_staff`?), so Top Out staff can create a login and Sit Start never deletes or signs out one Top Out uses. Removing someone from Top Out staff keeps their login. Sign Out here is this device only (`scope: 'local'`).
- **Shared emails:** Supabase has one template per email for the project. `supabase-emails/build.sh` (repo root) joins `topout/supabase/emails/*.html` and `sitstart/supabase/emails/*.html` into `supabase-emails/*.html` with `{{ if .Data.topout }}`; those are what get pasted into Supabase. `sendLink` passes `topout: true` for a new login and `team_stamp_sender()` writes it (and `sent_by`) on an existing one; Sit Start's `stamp_sender()` sets it back to false.
- Switching a location's tabs (Summary, Calendar, Team) skips the Loading step: `locationPage` keeps the shown tab (its `nav.tabs[data-loc]`), lighting the new tab at once, until the next one draws (the user asked).
- `redraw()` re-runs the route after a save, without the Loading step and keeping the scroll (`redrawing` in `view`). `navToken` stops a slow page drawing over a newer one.

## Accounts

- `team_staff(id, email, first_name, last_name, name, pronouns, roles, invited_at, owner)`: `roles` ⊆ {admin, coach}. Admins see every location, the Staff page and Settings. Coaches see the locations in `team_staff_locations(staff_id, location_id)`. The owner (set only in the SQL Editor) always keeps Admin and can't be removed (`team_protect_owner`); there is always an admin (`team_keep_an_admin`); nobody removes themselves or takes Admin off themselves.
- Staff page: + Add Staff inserts the row, ticks locations and sends the invite (`sendLink`, then `invited_at`). Typing an email Sit Start knows (`team_staff_lookup`, admins only: Sit Start staff, else students) fills in any empty name and pronoun fields (`watchLookup`, `setPronouns`), and if that login already has a password (`encrypted_password` set) there is no invite: they are added, `invited_at` is stamped, and they sign in with the password they have (the user asked for no password change). Sit Start's Add User does the same the other way, through `person_in_other_app()`, which this schema replaces to read `team_staff`. Clicking a person opens the same dialog to change name, roles and locations, Remove them, or use the Resend Invite / Email a Sign-In Link button (sends at once; the result shows in the dialog, since a flash would sit behind it; the user wanted a button, not a checkbox). Status: Active (has signed in), Invited, Not Invited.
- **One name everywhere:** `person_pull` / `person_push` triggers (this schema) keep first name, last name and pronouns the same on `staff`, `students` (Sit Start) and `team_staff` rows with the same email (the user asked for this). A row that newly gets an email someone already has, or has no first name, adopts the existing name; after that any change copies to the others (last save wins). `team_members` are not logins and are not synced.
- Sign-in pages copy Sit Start's: password sign-in, Forgot Password (same answer either way), Choose a Password after a link (`?setpw=1`).

## Data

- `team_locations(id, name, position)`: Home's cards in `position` order (a solid orange line on top). A location with members can't be deleted (FK restrict on `team_member_locations`).
- `team_member_locations(member_id, location_id, inactive_on)`: the teams a member is on, usually one, possibly several (the user asked for this). `inactive_on` set = inactive on that team (switched locations but kept on its list; the user asked): Details has an Active / Inactive pick by each ticked team; there they show under Former with an Inactive since chip, and they are left out of Home counts and the Summary; other teams show Also X or Formerly X; on Team Members, All Locations puts them under Former only if inactive on every team. Add to <location> on an inactive one makes them active (`team_join_location`). `inactiveOn(m)` / `activeOn(m, id)` in location.js. Migration `2026-10-02-inactive-teams.sql`. Left the Team (`left_on`) is still for leaving Adult Team. `team_can_member` = admin or a coach at any of their teams. A coach adds or takes off only their own locations; Details shows Teams checkboxes (at least one) and a hint for teams they can't see. New members come in through `team_add_member()` (security definer: member and first team together, since a member with no team can't be read back). The member page's breadcrumb goes back to the list they came from (`lastLoc`: a location they're on, or `'members'`).
- `team_members(id, first_name, last_name, name, pronouns, email, joined_on, left_on, intake_*)`: `left_on` set = Former (Left the Team; Back on the Team clears it). Intake is filled in by a coach: why they joined, what they want from Adult Team, comps (yes/maybe/no/''), injuries or limits, anything else. The user said no availability (practice days are fixed). An empty intake (why and wants) shows Needs Intake.
- `team_goals`: current / achieved / archived; `team_goal_done` sets `done_at`.
- `team_coach_notes`: `note_date` (practice) or empty (general). Author or admin edits/deletes. `team_stamp_author` signs notes, check-ins and events.
- `team_circuits(name, color, position, v_min, v_max)`: the gym's circuit colors, easiest first, same at every location: Yellow V0, Red V0–2, Green V1–3, Purple V2–4, Orange V3–5, Black V4–6, Blue V5–7, Pink V6–8, White V8–10, Mint V11+. Admins edit them in Settings; one used by a check-in can't be deleted.
- `team_rating_areas(name, position, active, area_group, rated, guide)`: the screens call them Focus Areas everywhere (the user renamed them from Areas; code and tables keep `area`). `area_group` physical / skill / mental (the strength-vs-skill split the coach wanted). `rated` areas get 1–5 ratings (Technique, Strength, Endurance, Mental Game, Footwork); the others are tag only (Flexibility, Volume, Comp Prep). `guide` = five lines, what each number means for that area (Focus Area Ratings in Settings, listed under the area name above its ratings on a check-in; a blank line falls back to `RATING_GUIDE`), so coaches rate the same way. Hide keeps old ratings. Every area can be deleted (the user asked): the confirm says how many check-ins use it, and `team_area_cleanup` takes its ratings and tags off them and off Team Focus.
- `team_checkin_questions(prompt, hint, position, active, tags)`: what a coach asks at a check-in (defaults: Proud Of, Want to Improve with `tags`, Competition Thoughts, always shown since not every comp is on the calendar). Admins add, edit, reorder, hide; one with answers can't be deleted. `hint` is the example in the empty box.
- `team_checkins`: any cadence (the user wasn't sure: monthly to yearly). Hardest circuit, Tension Board 2 and Kilter (V grade + angle), outdoor/other boulder V, route YDS (the gym is bouldering only, but members climb ropes), `ratings` jsonb `{area id: 1..5}` = the member's own rating (the coach taps it for them; labeled with their first name on the check-in, Member on the Summary; the hint uses their pronouns via `pronounWords`), `coach_ratings` = the coach's (the user wanted both), `answers` `{question id: text}`, `tags` `{question id: [area ids]}`, notes. The newest shows in full with ↑/↓ against the newest older check-in that has that value; older ones fold into History. Each is signed "Check-in by <name>" (no per-rating attribution or different-coach marker: the user said no). A new check-in starts as a copy of the latest (grades, both ratings, notes; not answers or tags; dated today). A 1–5 rating clears by tapping the picked number again (no × button; the user asked). The dialog goes Questions, Grades, Ratings, Notes, with a line between sections; the card shows answers, grades, then ratings.
- `team_focus(location_id, focus_date, body, area_ids)`: Team Focus, what the coaches decide the team works on. Dated; earlier ones fold under Earlier. Any coach at the location adds, edits or deletes (signed by `team_stamp_author`).
- `team_practices(name, summary, area_ids, blocks, author_*)`: Practices, a library every coach shares wherever they coach (the user asked: like Sit Start's Exercises & Drills), so RLS is `team_is_staff()` for everything. `blocks` jsonb `[{id, title, minutes, notes}]`, every field optional (the user asked), any length 1–600 min. Only the name is required. `area_ids` tag what it works on, for the list's Area: filter; `team_area_cleanup` takes a deleted area off. Migration `2026-10-02-practices.sql`.
- `team_events`: calendar, `kind` competition / practice / open_house / other, one day or several (`end_date`), all day or timed, place, notes. `location_ids` = the locations it shows at (the Show At boxes), null = every location (admins only; ticking Every Location ticks every box). A coach changes an event only if all its locations are theirs (`team_can_all_locations`); a deleted location comes off its events (`team_drop_event_location`). Repeats Weekly (Add only: weekdays + Until, at most 200) inserts one row per day with a shared `series_id`; Edit and Delete on one of them ask This Event Only / This and Later Events (later ones keep their dates). No attendance (the user said the calendar is for coaches to know the plan). Opening the Calendar tab starts at this month; picking a day or month uses `redraw()` (no Loading flash). An event clicked in Home's Coming Up sets `calOpen`: the calendar starts at its day and opens it. A new event starts as Practice, 6–8 PM (the user's practice time). Any event but a Competition can link to a practice (`practice_id`, `hasPlan`; Practice Plan in the dialog; the user added Open House and Other; the event shows a Practice Plan button that opens it). The calendar reads `team_practices` leniently so it still works before the migration.
- Forms: Save and Add buttons (`.primary`) are greyed out (disabled by `markUnsaved`) until a field changes, then orange, filled on hover. An edited card gets an orange border, tint and Unsaved tag; Settings rows light up on their own. Color inputs compare ignoring case (they read back lowercase). Delete/Leave confirm buttons (`warn`) are a red outline (`.risky`), filled on hover. Enter in a dialog field presses OK. Field errors go inside the label. A required field gets a small red * after its label (`markRequired` in core.js, a MutationObserver; `fieldset[data-required]` stars the legend for pick-at-least-one groups; the user asked). Team members need first and last name, pronouns and date joined.

## Conventions

- Look: "Chalk & Rope": chalk-white page, deep navy ink, rope-orange accent; Space Grotesk headings, Figtree body. Tokens on `:root` with dark mode. The user's fallback if they go off it: "Granite & Sky" (cool grays, slate-blue accent).
- Logo: a boulder with a flag on top (inline SVG in the header and on the root home card; `icon.svg` is the favicon). `apple-touch-icon.png` (180px, chalk mountain and orange flag on navy) is for phone home screens, drawn with PowerShell System.Drawing from the same points as the SVG, so redraw it if the mark changes.
- Works at ~400px wide. Title case for buttons, headings and labels; sentence case for hints and messages.
- Dialogs use `ask()` (`wide` for big forms, `extra` for a Delete/Remove button, `onOpen` to wire fields, `cancelLabel`). One `#dlg` for all: its close event comes late, so `ask()` skips a close while its own form is up (one pop-up opening another, like Practice Plan from an event). `wireGrips(moved, root)` takes the form to look in.
